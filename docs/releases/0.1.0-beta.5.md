# Sleeper Draft Assistant 0.1.0-beta.5

Windows prerelease testing candidate, not stable-release approval. Complete the
real Windows smoke before tagging. Beta updates may break compatibility. Close
beta.4 and back up the complete app-data directory before upgrading.

## Changes

- Security dependency updates include Electron 43.8.3, patched Undici dependencies,
  and a migration to Zod 4. Earlier updates also patched Hono, Vite, and build
  dependencies. Input validation and persisted-record compatibility remain covered
  by contract tests. See [#52](https://github.com/itsreverence/sleeper-draft-assistant/pull/52)
  and [#42](https://github.com/itsreverence/sleeper-draft-assistant/pull/42).
- FantasyPros projection files renamed by the browser, such as `_K (4).csv`, now
  import. Season and weekly uploads share position detection for download suffixes,
  lowercase filenames, and quoted or unquoted headers.
  See [#56](https://github.com/itsreverence/sleeper-draft-assistant/pull/56).
- FantasyPros Overall ROS rankings exported with the shorter `SOS`, `PLAYOFFS`,
  and `ECR VS ADP` column labels now import as season value rankings. The
  earlier `SOS SEASON` / `SOS PLAYOFFS` / `ECR VS. ADP` layout still works.
  See [#59](https://github.com/itsreverence/sleeper-draft-assistant/pull/59).
- On Windows, the default `codex` setting now finds an npm-installed Codex at
  `%APPDATA%\npm\codex.cmd` even when that folder is missing from the PATH the
  app inherited from Windows.
  See [#60](https://github.com/itsreverence/sleeper-draft-assistant/pull/60).
- In one-QB leagues, **Pass on QB?** appears among the first three draft questions
  until you draft a QB. Sleeper's `SF` alias is recognized as superflex, so those
  leagues do not receive the single-QB question.
  See [#54](https://github.com/itsreverence/sleeper-draft-assistant/pull/54)
  and [#49](https://github.com/itsreverence/sleeper-draft-assistant/pull/49).
- Restricted flex slots now follow Sleeper's rules. `WRRB_FLEX` accepts RB or WR,
  and `REC_FLEX` accepts WR or TE. Starter feasibility and the required-position
  board filter share slot counting, including superflex.
  See [#44](https://github.com/itsreverence/sleeper-draft-assistant/pull/44).
- Research instructions use the citation validator's approved host list without
  guessing or rewriting source URLs. Muted text has better contrast, draft chat
  has a persistent accessible name, and coverage and provider readiness have
  appropriate accessible semantics.
  See [#41](https://github.com/itsreverence/sleeper-draft-assistant/pull/41).

### Tests, CI, and release gates

Tests check composed HTTP redaction, token requirements with `Origin: null`, news
URL rejection, stale responses, evidence ordering, Electron window security, and
the built renderer's CSP. CI runs bounded exhaustive roster-feasibility checks.

Windows CI checks a clean-profile install and upgrade from the checksum-verified
previous release, preserving settings, guidance, rankings, season projections,
ADP, and decision history. It also checks installed diagnostics/support-report
redaction, guidance clear and full API reset across relaunch, native occupied-port
Retry/Exit, loopback authentication, data placement and private ACLs, uninstall
retention, and portable startup. Renderer readiness proves mounted content, not
interactive UI behavior. See [#58](https://github.com/itsreverence/sleeper-draft-assistant/pull/58).
Release publication verifies the original build artifacts on a separate runner
and preserves their unmodified bytes.

## Manual checks

This version is tagged only after the every-release
[real Windows smoke](../RELEASING.md#real-windows-smoke) passes on
the exact tagged commit's CI candidate, in a real desktop session with a clean
Windows user profile. That smoke covers launch, a live Sleeper connection, a
user-owned FantasyPros import through the native file picker, one local Codex
question, and SmartScreen behavior for the unsigned download. The maintainer's
results are recorded on [#57](https://github.com/itsreverence/sleeper-draft-assistant/pull/57).

The fuller [once-before-stable pass](../RELEASING.md#once-before-the-first-stable-release)
is still pending for this beta. It covers demo/keyboard/focus/scaling, native
import variations, news citation dispatch and unsafe links, Codex recovery,
shutdown during AI/research, populated ROS/weekly/draft-plan clears and reset,
renderer clear/reset and preference cleanup, backup restore/rollback, and
interactive installer/uninstall/reinstall with normal-user profile access.

Do not claim Windows readiness based only on Linux packaging or CI. A real
clean-profile Windows launch remains the final distribution gate.

## Safety and rollback

Artifacts are unsigned and may trigger SmartScreen. Install only this repository's
release artifacts after checking their SHA-256 checksums. Sleeper is the only
supported fantasy platform. Access is tokenless and read-only. The app does not
submit picks, change lineups, or modify your Sleeper account.

Supply your own ranking and projection exports. No third-party ranking data is
bundled. Normal AI use requires a locally installed, authenticated Codex CLI through
the supported app-server integration. Active drafts retain emergency board-only
recovery when setup or Codex is unavailable. Validate AI advice yourself. IDP and
auction advice are unsupported. Dedicated dynasty/keeper valuation is not modeled,
and custom scoring accuracy depends on matching imports. News lookups can time out.

Local data normally lives under `%APPDATA%\Sleeper Draft Assistant`, with the
database in its `data` directory. Settings provides category clears and
**Delete all local app data**. The uninstaller retains local data. Close the app
before manually deleting `data` to remove substantive records, or the complete
application-data directory to also remove renderer convenience preferences.

Before upgrading from beta.4, close the app and back up the entire
`%APPDATA%\Sleeper Draft Assistant` directory, not only `data`. To roll back,
close beta.5, restore that pre-upgrade backup, and reinstall or run beta.4 from its
original release. Never restore a backup while either version is running. Beta
database changes may not be backward compatible.
