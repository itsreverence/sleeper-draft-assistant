# Sleeper Draft Assistant 0.1.5

This is a stable release following 0.1.4. It fixes six problems with failed
loads, cleared data, keyboard focus and the demo. Most of them fixed limitations
listed in the 0.1.4 notes.

The data format is unchanged, and 0.1.4 can read data written by 0.1.5 (see
[Rollback](#rollback)). Releases before 1.0 may change stored data or behavior
between versions. Close 0.1.4 and back up the complete app-data directory before
upgrading.

## Behavior changes to know about

- **A failed team load shows an error and a retry.** The message reads "Team
  couldn't load" followed by the reason, with a **Retry team load** button.
  Keyboard focus moves to that button whenever a team load fails, including when
  the app opens a draft at startup. A failed background refresh still shows the
  earlier team with a failed-refresh notice instead.
  See [#99](https://github.com/itsreverence/sleeper-draft-assistant/pull/99).
- **Try a demo draft always starts a fresh demo.** It used to reopen a demo you
  had already finished. If the app can't reset the demo, it shows an error and
  you can try again.
  See [#99](https://github.com/itsreverence/sleeper-draft-assistant/pull/99).
- **Team Manager uses the draft board's team.** When you paste a draft ID and type
  a roster value or slot that the draft doesn't have, the draft board shows the
  first team. Team Manager now loads that same team instead of the value you
  typed.
  See [#99](https://github.com/itsreverence/sleeper-draft-assistant/pull/99).
- **Cleared weekly projections leave the screen at once.** After **Clear week**
  succeeds, the week's projection summary and the lineup's projected points go
  away before the app refreshes the team. If that refresh fails, they stay gone.
  Clearing season value rankings works the same way.
  See [#99](https://github.com/itsreverence/sleeper-draft-assistant/pull/99).

## Changes

### Fixes

All six fixes are in
[#99](https://github.com/itsreverence/sleeper-draft-assistant/pull/99).

- If your team fails to load after you switch league or draft, the app now says
  so and offers **Retry team load**. Before, the team disappeared with no message.
- If you typed a roster slot and a load of another week fails, your team and the
  loaded week now stay on screen with the error. Before, the team disappeared.
- A failed refresh after an import or clear now reads as a failed refresh, not as
  "Week N didn't update". Data you cleared no longer comes back while the refresh
  is failing. Clearing rankings in a connected draft also removes the Team Manager
  value rankings that came from that draft's file.
- If an import for another week fails, the header, the lineup and the Assistant
  all keep the week that is actually loaded.
- In **Settings > Local data**, keyboard focus now stays useful. Opening a clear
  focuses **Cancel**. **Cancel** returns focus to the row's clear button. After
  **Confirm**, focus moves to the next row you can clear, or to the **Local data**
  line when there is none.
- **Try a demo draft** now resets the demo to its opening picks, even after a
  finished demo. An older demo can no longer move the new board forward.

### Release process

- The clean first run before each release can now use Windows Sandbox as well as
  a temporary local Windows account.
  See [#98](https://github.com/itsreverence/sleeper-draft-assistant/pull/98).

## Tested platforms

Windows 11 Pro 26H2 (build 26300.9711) is the only platform the release checks
use. A release is published only after two human checks pass on its exact
commit: a clean first run in Windows Sandbox or on a temporary Windows account,
and the full interactive smoke on an upgraded profile. CI's automated Windows
package smoke doesn't replace either one. Linux packaging and CI do not establish
support on other Windows versions or operating systems.

## Install safely

Artifacts are **not code-signed**, and Windows SmartScreen may warn that the
publisher is unknown. Download only from this repository's Releases page and
check each file's SHA-256 against `SHA256SUMS.txt` before running it. See
[INSTALLING.md](../INSTALLING.md). Third-party licenses are in
`resources\THIRD_PARTY_NOTICES.txt`.

## Requirements and limitations

- Sleeper is the only supported fantasy platform. Access is tokenless and
  read-only. The app does not submit picks, change lineups or modify your
  Sleeper account.
- You supply your own ranking and projection exports. No third-party ranking
  data is bundled.
- The normal assistant workflow requires a locally installed, signed-in Codex
  CLI, which the app runs through its supported app-server integration. During
  an active draft, board-only recovery remains available when setup or Codex is
  unavailable.
- AI advice is advisory; check it yourself. News lookups can still time out or
  find no recent reporting. Citation dates are reported by the model and are
  checked for format, recency and consistency with the link, but not against
  the publisher's page.
- Automatic Assistant calls in the draft room skip live news and use the status
  metadata Sleeper supplies. Typed questions and **Retry** can still check news
  when Web search is on.
- Custom scoring and TE-premium accuracy depend on imports that match your
  league. IDP and auction drafts are unsupported. Dynasty and keeper valuation
  is not modeled. The app handles keeper pick order but does not value keepers.
- Linear, third-round-reversal and keeper order have not been tested on a live
  draft in progress.
- Sleeper's injury status is general player information, not specific to the
  week you are viewing.
- Automated tests of the redesigned screens used synthetic data.
- The app shows no pick timer, because it does not read one from Sleeper.
- The app has a dark theme only.
- Research threads disable Codex's built-in shell, browser, computer-use, app
  and plugin tools. They do not disable MCP servers you have configured in your
  own Codex setup.
- The app is not code-signed. See [Install safely](#install-safely).

## Local data and removal

Data normally lives under `%APPDATA%\Sleeper Draft Assistant`, with the database
in its `data` directory. The **Local data** line in Settings offers per-category
clears and **Delete all local app data**. The uninstaller keeps local data. Close
the app before deleting files by hand: delete `data` to remove your records, or
delete the whole directory to also remove renderer preferences.

## Rollback

The data format is unchanged. No storage, shared-schema or desktop code changed
between 0.1.4 and 0.1.5, the database schema version is still 1, and the app
saves the same browser preferences. The only API change is a route that resets
the demo's picks in memory, which stores nothing. 0.1.4 can read data written by
0.1.5 and no restore is required. To roll back:

1. Close 0.1.5.
2. Reinstall 0.1.4 from its original release.

If you would rather return to exactly what you had before upgrading, restore
your backup between those steps. That discards anything imported or saved since.
Never restore a backup while either version is running.

If you roll back, the six problems fixed in 0.1.5 come back. Your data is not
affected.
